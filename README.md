# 금치 프리미엄 알림 봇

국내 금값과 국제 금값의 괴리(금치 프리미엄)를 매일 아침 텔레그램으로 받는다.
프리미엄이 벌어지면 국제금 ETF로, 정상화되면 국내 금현물 ETF로 갈아타는 전략용.

---

## 전략

```
평소:  TIGER KRX금현물 (0072R0) 보유
프리미엄 ≥ 5%  →  다음 거래일 KODEX 금액티브 (0064K0) 로 교체
프리미엄 ≤ 1%  →  다음 거래일 TIGER 로 복귀
```

두 ETF 모두 환노출이라 원/달러 요인이 상쇄되고 프리미엄 변동만 남는다.
연금저축 계좌에서 운용하면 전환할 때마다 과세되지 않는다.

### 2년 백테스트 (2024-08 ~ 2026-08)

| | 총수익 | 전환 |
|---|---|---|
| 매수후보유 (국내 금현물) | +87.30% | — |
| 볼린저 밴드 (μ+2.9σ) | +76.88% | 14회 |
| **절대 5% / 1%** | **+155.73%** | 8회 |

임계값 조합 49개 전부가 매수후보유를 초과했다. 좁은 최적점이 아니라 넓은 고원.

실제 발동 4회, 4회 모두 진입 후 프리미엄이 1% 이하로 수렴:

| 매수일 | 매도일 | 진입 프리 | 청산 프리 | 상대수익 |
|---|---|---|---|---|
| 2024-10-25 | 2024-11-08 | 5.27% | 1.20% | +4.71%p |
| 2025-02-06 | 2025-03-18 | 9.38% | 1.17% | +10.62%p |
| 2025-09-19 | 2025-10-28 | 2.84% | 0.07% | +4.42%p |
| 2026-02-02 | 2026-02-10 | 7.81% | 0.44% | +2.36%p |

## 한계 — 반드시 읽을 것

- **표본이 4개뿐이다.** 통계적 검증이 아니라 관찰 수준. 최대 트레이드 하나가 알파의 48%.
- **체결 지연에 취약하다.** 신호 다음 거래일 실행이 +155.73%, 하루 더 밀리면 +126.24%.
- **금값이 오르지 않으면 발동하지 않는다.** 프리미엄 3% 이상이던 57일은 100% 금값 상승기였다.
- **2026-04-18 KRX 금시장 개방 효과는 미검증.** 다음 금값 상승기가 첫 시험대.
- **차익거래가 아니다.** 공매도 다리가 없으므로 방향성 베팅이다. 손실 가능성이 있다.

투자 자문이 아니다.

## 작동 원리

KRX 사이트 스크래핑(Akamai WAF 차단)도 증권사 API도 쓰지 않는다.
**두 ETF의 NAV 비율**만으로 프리미엄 수준을 복원한다.

```
비율      = TIGER_NAV / KODEX_NAV
프리미엄(%) = (비율 / 앵커비율 - 1) × 100 + 앵커프리미엄
```

TIGER는 `국제금값 × (1+프리미엄)`, KODEX는 `국제금값`을 따라가므로
비율에서 금값 요인이 상쇄되고 프리미엄만 남는다.
비율 자체는 상장 시점 NAV 기준이 달라 의미가 없고, **변화량만 쓴다.**
그래서 한 번은 실제 프리미엄 값으로 기준점(앵커)을 잡아줘야 한다.

**종가가 아니라 NAV를 쓴다.** 종가에는 시장가-NAV 괴리가 섞여 있다.
(2026-09-04 실측: TIGER 괴리율 +0.13%, KODEX +0.09% → 0.04%p 오차)

## 설정 (한 번만)

### 1. 텔레그램 봇

`@BotFather` → `/newbot` → 토큰 발급.
봇과 대화방을 열고 아무 메시지나 하나 보낸다.

chat_id 확인:
```
https://api.telegram.org/bot<토큰>/getUpdates
```
응답의 `"chat":{"id":123456789` 숫자.

### 2. GitHub Secrets

Settings → Secrets and variables → Actions → New repository secret

| 이름 | 값 |
|---|---|
| `TELEGRAM_BOT_TOKEN` | BotFather 토큰 |
| `TELEGRAM_CHAT_ID` | 위에서 확인한 숫자 |

**이게 전부다.** API 키도, 종목코드도, bld 값도 필요 없다.

### 3. 테스트

Actions → `금프리미엄 알림` → `Run workflow`.
텔레그램이 오면 완료.

## 알림 내용

평일 **05:40 KST** 발송. 장 시작 전에 전 거래일 종가 기준 프리미엄을 받는다.
신호가 없는 날에도 매일 보낸다. 조용하면 봇이 죽은 건지 신호가 없는 건지 알 수 없기 때문.

| 프리미엄 | 표시 | 행동 |
|---|---|---|
| ≥ 5% | 🚨 전환 신호 | 오늘 KODEX(0064K0)로 교체 |
| ≥ 3% | ⚠️ 관찰 | 1~2일 내 5% 돌파 가능 |
| 1~3% | · 중립 | 유지 |
| ≤ 1% | ✅ 평상 | 국제금 보유 중이면 TIGER로 복귀 |

3% 관찰 단계의 리드타임은 실측 **1~2일**뿐이다.
2년간 3% 경보 14회 중 10회가 실제 5%에 도달.

매매는 **09:05~15:20** 사이 지정가로. 이 시간 밖에는 LP 호가 의무가 없어
스프레드가 벌어진다.

## 재앵커링

두 ETF의 보수 차이, KODEX의 액티브 재량, 재간접 이중 보수 때문에
시간이 지나면 계산값이 실제 프리미엄에서 조금씩 벗어난다.
KODEX 비용이 더 크므로 **프리미엄이 실제보다 높게 계산되는 방향**으로 밀린다.
방치하면 가짜 5% 신호가 뜬다.

### 방법 — 버튼 하나 + 숫자 하나

1. goldkimp.com 에서 현재 프리미엄 확인 (예: `1.24`)
2. Actions → **재앵커링** → `Run workflow`
3. 입력칸에 그 숫자를 넣고 초록 버튼

끝. `anchor.json` 이 자동으로 갱신·커밋되고,
텔레그램으로 **누적 드리프트가 얼마였는지** 알려준다.
파일을 직접 고칠 일이 없다.

### 주기

**한 달에 한 번.** 앵커가 35일을 넘기면 알림에 경고가 붙는다.

드리프트가 매번 얼마나 쌓이는지 기록해두면 감이 잡힌다.
`premium_log.csv` 의 `premium_actual` 칸에 가끔 goldkimp 값을 적어두면
나중에 계산값과 나란히 비교할 수 있다.

### 처음 몇 주

**매일 goldkimp 값과 알림 값을 비교하세요.**
차이가 일정하면 드리프트, 들쭉날쭉하면 계산 방식에 문제가 있는 것이다.
5% 문턱을 실전에 쓰기 전에 이 검증을 먼저 통과시킬 것.

## 알려진 문제

**네이버 금융 응답 구조가 바뀌면 멈춘다.** 그때는 오류 내용이 텔레그램으로 온다.
`python etf_premium.py --probe` 로 응답 원문을 확인해 필드명을 맞추면 된다.

**KODEX 금액티브는 추적오차가 공표되지 않는다.** 액티브 ETF라 벤치마크 추종
의무가 느슨하다. "KODEX = 국제 금값"이라는 전제를 검증할 수치가 없다는 뜻이고,
이것이 드리프트의 주된 원인이다.

**현재 프리미엄은 0%대다.** 2026년 3월 이후 5%를 넘은 적이 없다.
몇 달간 "✅ 평상"만 반복될 수 있다. 그게 정상이다.
